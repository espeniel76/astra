# 아스트라 (ASTRA) — 설계

작성 2026-11-14. 이 문서는 아직 만들어지지 않은 새 게임의 설계다. 게임을 만들기 시작할 때 새 폴더의 `docs/superpowers/specs/`로 옮긴다.

표기: **[사용자]** = 사용자가 직접 정한 것, **[제안]** = 내가 정했고 사용자가 반대하지 않은 것, **[빌더]** = 만드는 사람이 정해도 되는 것.

## 1. 왜 만드나 / 누구용인가

- 유튜브 채널 끼발산의 개그 시리즈 「랜덤뽑기 RPG」에서 영감을 받았다. 그 시리즈의 웃음은 "화려한 연출 → 꽝"이라는 **기대 배신**이다. **[사용자]** 우리는 그 기대 배신을 없앤 **진짜 정석 뽑기 RPG**를 만든다.
- **[사용자]** 아들(대화하는 사람)이 12살 친구들에게 링크를 주고받으며 하는 정도의 게임이다. 앱 스토어, 과금, 광고는 없다.
- 끼발산의 캐릭터(비실이 등), 이름, 화면 모습은 가져오지 않는다. 구조만 참고한다.

## 2. 목표 / 하지 않을 것 / 실패 조건

**목표**
- 뽑기 → 육성 → 3인 팀 편성 → 스테이지 돌파의 정석 루프가 재미있게 돈다.
- 뽑기가 정직하다: 연출 = 결과, 확률 공개, 천장 있음, 실패하는 강화 없음.
- 휴대폰 브라우저에서 링크 하나로 바로 된다.

**이번 버전에서 하지 않을 것 (나중)**
- **[사용자]** 1대1 대전(PvP). 스테이지 모드를 먼저 만든다. PvP에는 서버(Firebase 등)가 필요하므로 지금은 만들지 않되, 저장 데이터를 나중에 옮기기 쉬운 모양으로 둔다(§10).
- 길드, 장비, 스토리 모드, 낚시 같은 미니게임, 상점(과금).

**실패 조건 (돌아가도 실패인 것)**
- 연출이 결과를 속이는 순간이 하나라도 있다(금빛이 나왔는데 낮은 별, 확정처럼 보이다가 바뀌는 연출 등).
- 강화·육성에서 영웅이나 재료가 날아가는 실패가 있다.
- 확률을 숨긴다.
- 영웅이 "흔한 직업 이름만 바꾼 것"이라 서로 구분이 안 된다(좀비 생존자에서 사용자가 거부한 방향).

## 3. 기술 / 만드는 방법

- **[사용자] 접근 B:** 메뉴 화면은 HTML/CSS(DOM), 전투와 뽑기 연출만 Phaser.
  - 검토했던 다른 길: A) 전부 Phaser — 좀비 생존자와 같지만 영웅 목록·스크롤·편성 메뉴를 그림으로 다 만들어야 하고 글자가 흐림. C) 전부 DOM — 가장 가볍지만 스킬·뽑기 연출이 밋밋해서 세븐나이츠식 전투와 안 맞음.
- **[제안]** 좀비 생존자(`c:\Users\mimis\git\좀비 생존자`)와 같은 기반: Vite 5 + Phaser 3.90 + Vitest, 세로 화면 720×1280 기준, 휴대폰 우선.
- **[제안]** 좀비 생존자와 **별도 폴더·별도 저장소**(좀비 생존자 배포와 엉키지 않게). 공개 GitHub 저장소 + GitHub Pages로 링크 공유(좀비 생존자의 `.github/workflows/pages.yml` 방식 그대로).
- 저장은 브라우저 localStorage. 서버 없음.
- UI 글자는 전부 한국어.

## 4. 세계관과 그림체

- **[사용자]** 판타지. 첫 지역은 **초원**이고 적은 **슬라임**.
- **[제안]** 그림체는 좀비 생존자와 같다: 정면을 보는 동그라미 몸 + 동공 없는 흰 눈 두 개, 모자·옷 색·든 무기로 구분. 좀비 생존자의 `src/render/blob.js`(`drawPerson`, `allyLook`, `drawWeapon`, OUTFIT 등)를 복사해 와서 쓴다. ★6·★7 영웅은 좀비 생존자와 **같은 모습**으로 나온다.
- ★1~★5 판타지 영웅에 필요한 새 무기·모자(검, 방패, 지팡이, 활, 망치, 투구, 두건 등)는 blob.js에 추가한다.
- 적(슬라임 등)도 같은 동그라미+흰 눈 그림체.
- 그림을 바꾸거나 새로 만들 때는 먼저 목업을 보여 주고 확인받는다(사용자가 좀비 생존자에서 원했던 방식).

## 5. 영웅

### 5.1 별 등급 [사용자]

★1~★7. 별은 영웅마다 고정이고 바뀌지 않는다(진화·합성 없음).

| 별 | 영웅 | 수 | 출처 |
|---|---|---|---|
| ★7 | 영원한 황금의 수호신 | 1 | 좀비 생존자 이터널 **[제안]** |
| ★6 | 전설 5 + 신화 17 | 22 | 좀비 생존자 **[사용자: ★6은 좀비 생존자 영웅]** |
| ★5 | 새 판타지 영웅 | 10 | 새로 |
| ★4 | 새 판타지 영웅 | 10 | 새로 |
| ★3 | 새 판타지 영웅 | 10 | 새로 |
| ★2 | 새 판타지 영웅 | 10 | 새로 |
| ★1 | 새 판타지 영웅 | 10 | 새로 |

- **[사용자]** ★1~★5는 판타지 인물로 새로 만든다(좀비 생존자의 현대 인물 일반~영웅 등급은 쓰지 않는다). "많이" 원했다.
- **[제안]** 첫 버전은 ★1~★5를 **별마다 4명씩(20명)** 만들고, 나머지 30명은 업데이트로 채운다. ★6 22명 + ★7 1명은 첫 버전에 모두 넣는다.
- ★6 명단(좀비 생존자 `src/data/allies.js`의 tier 4·5): 메아리술사, 도깨비불 술사, 자력술사, 폭탄 광대, 늪지 마녀 / 중력 조종자, 악마 계약자, 꼭두각시 인형사, 시간 도둑, 거울 기사, 꿈의 요정, 운명의 도박사, 처형인, 영혼 수집가, 용 조련사, 석화의 눈, 그림자 군주, 불사조 기사, 회오리 술사, 죽음의 황제, 영원한 황금의 군주, 역병 의사. 대사(quote)와 능력 이름(role)은 `HEROES` 그대로 쓴다.

### 5.2 새 영웅의 방향

- 별이 낮을수록 소박하고(견습 검사, 마을 궁수 급), 높을수록 강하고 멋있다(성기사, 대마법사 급).
- 좀비 생존자에서 사용자가 좋아한 결: 멋있고 영웅적이며, **규칙을 비트는 기술 하나**가 분명하고, 실루엣이 뚜렷하다. 우스꽝스럽거나 밋밋한 컨셉은 거부당했다.
- 흔한 직업 이름에 형용사만 붙인 영웅은 피한다. ★1이라도 기술 하나는 확실히 다르게.
- 새 영웅 명단은 만들기 전에 사용자에게 목록과 목업으로 보여 주고 확인받는다.

### 5.3 능력치와 역할

- 능력치: 체력, 공격, 방어, 속도. **[빌더]** 구체적인 수치와 별에 따른 배율.
- **[제안]** 역할 표시: 탱커 / 딜러 / 지원(회복·버프). 3인 편성에 고민거리가 생기게 한다.
- ★6·★7은 좀비 생존자 고유 능력을 **턴제 스킬로 옮긴다.** 핵심 규칙은 유지(처형인 = 체력 30% 이하 즉사, 시간 도둑 = 적 정지, 꿈의 요정 = 잠재운 뒤 깨우며 큰 피해, 운명의 도박사 = 주사위 6이면 대박 등). 좀비 생존자에서 "기지"에 걸려 있던 능력(거울 기사 반사, 불사조 기사 부활, 악마 계약자, 수호신 부활)은 "아군 팀 체력" 기준으로 바꾼다. **[빌더]** 세부 수치와 옮기는 방식.

### 5.4 육성 [사용자 + 제안]

- **[사용자] 겹치기:** 같은 영웅이 또 나오면 그 영웅이 조금 더 세진다.
  - **[제안]** 이름 옆에 +1, +2… 표시, 한 번에 능력치 +10%, 최대 +5. +5 이후 겹치면 골드로 바꿔 준다(금액은 **[빌더]**).
- **[제안] 레벨업:** 스테이지에서 얻은 골드로 영웅 레벨을 올린다. 실패 없음. 뽑기 운이 없어도 키울 길을 주려는 것. 최대 레벨과 비용 곡선은 **[빌더]**.
- 실패하는 강화, 영웅이 사라지는 강화는 **없다**.

## 6. 전투 [사용자: 세븐나이츠식 턴제, 영웅 최대 3명]

```
[적1] [적2] [적3]        스테이지 1-3
   ↑ 차례대로 공격
[영웅1][영웅2][영웅3]
 (스킬)(스킬)(스킬)    [자동] [2배속]
```

- 내 영웅 최대 3명 vs 적 최대 3마리.
- 속도 순으로 차례가 돌고, 기본 공격은 자동으로 나간다.
- 영웅마다 스킬 1개. 쿨타임(턴 단위)이 차면 버튼이 켜지고 **직접 누른다**. 누르면 그 영웅의 다음 차례에 스킬이 나간다(또는 즉시 — **[빌더]**, 템포 좋은 쪽으로).
- **자동** 버튼: 스킬도 알아서 쓴다. **2배속** 버튼.
- 적 전멸 = 승리, 아군 전멸 = 패배. 패배해도 잃는 것 없음.
- 보스는 패턴이 있는 큰 적(예: 킹 슬라임 — 체력이 줄면 작은 슬라임으로 분열).
- 전투 판정 로직은 화면과 분리해 순수 함수로 두고 Vitest로 검증한다(나중에 PvP에서 같은 로직 재사용).

## 7. 스테이지 모드 [사용자: 스테이지 모드 먼저]

- 챕터 = 스테이지 10개, 10번째가 보스. 순서대로 열린다.
- **[제안] 첫 버전 3챕터:**

| 챕터 | 장소 | 적 | 보스 |
|---|---|---|---|
| 1 | 초원 | 슬라임, 들쥐, 벌 | 킹 슬라임 |
| 2 | 숲 | 고블린, 늑대, 버섯 | 고블린 족장 |
| 3 | 동굴 | 박쥐, 골렘, 거미 | 바위 거인 |

- 스테이지 하나는 적 1무리(최대 3마리), 보스 스테이지는 보스 + 졸개. **[빌더]** 여러 무리 연속 여부.
- 보상: 골드(매번), 다이아(처음 깰 때만). **[빌더]** 수치(§8 경제 기준 참고).
- 다시 하기 가능(골드 파밍).

## 8. 소환(뽑기)과 경제

### 8.1 규칙

- 1회 100다이아, 10+1회 1,000다이아.
- **[제안] 확률(화면에 공개):** ★1 40% / ★2 28% / ★3 18% / ★4 9% / ★5 4% / ★6 0.9% / ★7 0.1%. **[빌더]** 합이 100%가 되게 다듬는 정도는 가능, 큰 틀 유지.
- **[제안] 천장:** ★6 이상이 50회 동안 안 나오면 다음 1회는 ★6 이상 확정. 남은 횟수를 소환 화면에 표시한다.
- 같은 별 안에서는 영웅 균등 확률.

### 8.2 정직한 연출 (핵심)

- 소환 빛 색 = 이번 소환의 **최고 별 등급** 그대로(★1~2 흰빛, ★3 파랑, ★4 보라, ★5 주황, ★6 빨강, ★7 금빛 — **[빌더]** 색 조정 가능). 10+1회는 가장 높은 별 색.
- 빛이 바뀌거나, 좋은 척하다 꽝이 되는 "속임 연출"은 금지.
- 카드 공개 순서: 낮은 별부터 → 높은 별 마지막(기대를 키우되 배신하지 않음). 전부 건너뛰기 버튼.
- **[사용자] 컷신: ★6부터.** ★6·★7이 나올 때마다 그 영웅의 등장 컷신(영웅이 크게 등장 + 이름 + 대사, 좀비 생존자 영웅 등장 연출처럼)을 보여 준다. 처음 얻은 영웅이면 "NEW" 표시. ★7은 더 길고 화려하게. 탭하면 건너뛰기. 번쩍임 없이도 멋있게(빛줄기·천천히 밝아짐·글자 등장).

### 8.3 다이아 들어오는 곳 [제안]

- **[사용자] 목표 길이: 3챕터를 다 깨는 데 약 3일.** 하루에 1챕터 정도. 3일 동안 소환 약 110회 → ★6을 2~4명 보게 맞춘다.
- 시작 보상 3,000다이아(첫 10+1회 세 번 = 첫날부터 팀을 짤 수 있게).
- 스테이지 첫 클리어: 일반 150, 보스 1,000.
- 일일 미션 3개, 각 100다이아(예: 전투 5번, 소환 1번, 레벨업 1번). 하루마다 초기화.
- 합계: 3,000 + 27×150 + 3×1,000 + 3일×300 ≈ 10,950다이아 ≈ 소환 110회.
- 난이도는 하루에 1챕터 정도 막히게: 챕터 보스는 그날 뽑은 영웅을 레벨업해야 깨지는 정도. **[빌더]** 세부 수치(위 합계·목표는 지킨다).
- 과금 없음.

## 9. 화면

- **로비:** 팀 3명이 서 있는 메인 화면 + 모험 / 소환 / 영웅 / 편성 / 미션 버튼, 위에 다이아·골드.
- **모험:** 챕터 → 스테이지 선택(잠김·클리어 표시).
- **전투:** Phaser 화면(§6).
- **소환:** 1회 / 10+1회 버튼, 확률 보기, 천장 남은 횟수, 연출(Phaser).
- **영웅:** 보유 영웅 목록(별·레벨·겹침 정렬·필터) + 못 얻은 영웅은 실루엣(도감 겸용). 상세에서 레벨업.
- **편성:** 3칸에 영웅 배치.
- **일일 미션.**
- **설정:** 소리, 번쩍임 효과(아래).

## 10. 저장

- localStorage, `version` 필드 포함.
- 데이터 모양은 나중에 서버로 옮기기 쉽게: `{ version, diamonds, gold, heroes: { [heroId]: { level, dupes } }, team: [id, id, id], stages: { cleared }, pity, daily: { date, progress } }`. **[빌더]** 세부.

## 11. 반드시 지킬 것

- **번쩍임 안전:** 모든 효과에 번쩍이지 않는 대안이 있어야 하고, 번쩍임은 기본 꺼짐(사용자 아버지 발작 걱정 — 좀비 생존자와 같은 원칙). 소환 연출의 빛도 해당.
